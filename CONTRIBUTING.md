# Contributing to This Project

Thank you for considering contributing to this project! Please take a moment to review these guidelines to make the process easier for everyone.

## How to Contribute

### 1. Reporting Issues

- **Search First**: Please check the [issues](https://github.com/map-and-stream/log-armory/issues) page to see if your issue has already been reported.
- **Bug Reports**: If you find a bug, create a new issue with:
  - A clear and descriptive title.
  - Steps to reproduce the issue.
  - Expected and actual behavior.
  - Screenshots or logs if applicable.
- **Feature Requests**: Clearly explain the feature, why it would be useful, and any possible implementation ideas.

### 2. Pull Requests

- Fork the repository and create your branch from `main` (or the relevant branch).
- Write clear, meaningful commit messages.
- Make sure your PR addresses **one** issue at a time and refers to the corresponding issue number (e.g., `Fixes #123`).
- Make sure your code builds and passes all tests.
- Add or update documentation as needed.
- Describe your changes in the PR description, including the motivation and context.

### 3. Code Style Guide

- Follow the existing code style conventions used in the project.
- Use clear and descriptive variable and function names.
- Consistently format your code—run a linter or formatter if set up.
- Add comments where necessary to explain complex logic.

### 4. Commit Messages

- Use the present tense ("Add feature" not "Added feature").
- Use imperative mood ("Fix bug" not "Fixes bug" or "Fixed bug").
- Reference issues and pull requests liberally.

### 5. Code Review Process

- All PRs will be reviewed by a maintainer.
- Please address review comments and push changes.
- PRs may require approval and successful passing checks before merging.

---

We appreciate your efforts to improve this project! If you have questions, feel free to open a discussion or contact a maintainer.
